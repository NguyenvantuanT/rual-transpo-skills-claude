## Project

**Rual Transpo Rider Mobile** — Flutter app for a transportation/rider service (France market, French as default locale). Multi-flavor (dev / stg / prod) with auto_route navigation, Provider + MVVM, GetIt DI, Dio networking.

## Build / Run / Test

This project uses **FVM** (`.fvmrc` pins Flutter `3.44.0`). All `flutter`/`dart` commands below should be invoked through fvm so the pinned version is used:

```bash
fvm flutter pub get
fvm flutter pub run build_runner build --delete-conflicting-outputs   # regen router / gen / json
fvm flutter pub run intl_utils:generate                                 # regen l10n
fvm flutter gen-icons                                                   # regen app launcher icons

# Run (matches VS Code launch.json configurations)

# Two apps, two flavors each — Gradle uses `Rider` / `User`, source uses `rider` / `driver`.
# Note: Gradle flavor `developmentUser` corresponds to source file `main_driver_dev.dart`
# (commit 257446e renamed "User" → "Driver" in the Dart code, but the build.gradle.kts
# flavor names were left as-is).
fvm flutter run --flavor developmentRider -t lib/app/main_rider_dev.dart   --dart-define-from-file=.env.dev
fvm flutter run --flavor developmentUser  -t lib/app/main_driver_dev.dart  --dart-define-from-file=.env.dev
# Staging / prod entry points (`main_*_stg.dart`, `main_*_prod.dart`) still need to be created.

# Build APK directly
fvm flutter build apk --flavor developmentRider -t lib/app/main_rider_dev.dart  --dart-define-from-file=.env.dev
fvm flutter build apk --flavor developmentUser  -t lib/app/main_driver_dev.dart --dart-define-from-file=.env.dev

# Lint / format / test
fvm flutter analyze
fvm flutter format .
fvm flutter test                                          # run all tests
fvm flutter test test/path/to/specific_test.dart          # run a single test
```

> **Heads-up:** entry points are split per app: `lib/app/main_rider_dev.dart` (rider) and `lib/app/main_driver_dev.dart` (driver/user). `main_*_stg.dart` and `main_*_prod.dart` for both apps still need to be created following the same shape, swapping the env file and `Flavor.stg` / `Flavor.prod`.

## Environment files

There are **four** `.env*` files at the project root and **all four are currently tracked by git** (`.gitignore` does not list them). The app reads API base URLs, socket URLs, Google API keys, RevenueCat keys, and Appsflyer key from these via `flutter_dotenv`:

- `.env` — default/prod-like (MODE=prod), real `api-dev.xxx.fr` URL
- `.env.dev` — dev environment
- `.env.stg` — staging (`cme-api-stg.tekup.vn`)
- `.env.prod` — production (`api.cmemanager.vn`)

When adding new env vars, also update `pubspec.yaml`'s `flutter.assets` list (and the `flutter_gen.exclude` block).

## Architecture

```
lib/
├── rual_transpo_rider_app.dart   # Rider app Root MaterialApp.router
├── rual_transpo_driver_app.dart  # Driver (a.k.a. user-facing) app Root
├── app/                          # Entry points and app-wide config
│   ├── app_config.dart           # AppConfig singleton (baseUrl, flavor, keys)
│   ├── main_rider_dev.dart       # main(): loads env, sets up DI, runs RualTranspoRiderApp
│   └── main_driver_dev.dart      # main(): loads env, sets up DI, runs RualTranspoDriverApp
├── router/
│   ├── app_router.dart           # @AutoRouterConfig — declare routes here
│   └── app_router.gr.dart        # GENERATED by auto_route_generator
└── src/
    ├── base/                     # BaseViewModel + MixinBasePage (MVVM glue)
    ├── components/               # Shared UI: AppSnackBar, AppLoading, ServerError
    ├── constants/                # AppConstants, AppBaseUrl (reads from dotenv)
    ├── gen/                      # GENERATED by flutter_gen (assets.gen.dart, fonts.gen.dart)
    ├── generated/                # GENERATED by intl_utils (l10n) — also AppStyleScheme
    ├── l10n/                     # ARB source files (intl_fr.arb, intl_en.arb)
    ├── models/                   # Plain data classes
    ├── pages/                    # Feature pages, each in its own folder
    │   └── <feature>/
    │       ├── <feature>_page.dart   # Widget with `with MixinBasePage<FooVm>`
    │       └── <feature>_vm.dart     # extends BaseViewModel
    ├── resources/                # AppColor, AppColorScheme (ThemeExtension), AppStyle, AppStyleScheme
    ├── services/
    │   ├── local/                # SharedPrefs (token + user persistence)
    │   └── remote/               # ApiClient (Dio) + ApiInterceptor
    ├── theme/                    # AppTheme (lightTheme / darkTheme)
    └── utils/                    # locator (GetIt), appProvider (theme/locale state), extension
```

### MVVM pattern (enforced by base classes)

- **Page** extends `StatelessWidget` (or `StatefulWidget`) and mixes in `MixinBasePage<MyVm>`. The mixin wires up a `ChangeNotifierProvider`, dispatches loading/snackbar callbacks to view-model hooks, and renders one of five `ChangeState` views (`loading` / `blank` / `page` / `serverError` / `clone`).
- **ViewModel** extends `BaseViewModel` (which extends `ChangeNotifier`). Override `onInit()`; optionally `onAppear()` / `onDisAppear()` (declared `external` in the base class). Call `showLoading()` / `hideLoading()`, `changeState(ChangeState.serverError)`, `showError(message)`, `showErrorConnection()`, etc. instead of touching UI directly.
- ViewModels access `api` (Dio), `prefs` (SharedPrefs), and `appRouter` from the base class — they're all `locator<...>()`-backed singletons.

### Dependency injection (`src/utils/locator.dart`)

`GetIt` singleton named `locator`. Register new services in `setUpInjector()`. Call `locator<...>()` anywhere (do not pass through constructors unless the type is naturally testable in isolation).

### Routing (`router/app_router.dart`)

Uses `auto_route`. To add a route: add it to `routes`, annotate the page with `@RoutePage()`, then run `fvm flutter pub run build_runner build --delete-conflicting-outputs`. Generated file `app_router.gr.dart` — never edit by hand.

### Generated code (do not hand-edit)

- `lib/router/app_router.gr.dart` — `auto_route_generator`
- `lib/src/gen/assets.gen.dart` and `fonts.gen.dart` — `flutter_gen_runner`
- `lib/src/generated/l10n.dart` and `lib/src/generated/intl/*` — `intl_utils`
- Run all three generators together with `build_runner build`; the l10n one separately as noted above.

### Theming

`AppTheme` exposes `lightTheme` and `darkTheme`. The active theme uses two `ThemeExtension`s:
- `AppColorScheme` — semantic colors (`primaryText`, `divider`, `shadow`, `disabled`, `success`, `error`, etc.). Access via `context.appColor.<token>` (extension is defined next to `app_color_scheme.dart`).
- `AppStyleScheme` — typographic scale (`display36Bold` … `display10Regular`, two weights per size). Access via `context.appStyle.<token>`.

Both light and dark themes register both extensions; the dark variants re-color styles to `AppColor.white`. The `AppThemeMode` enum currently has a third value `kimia` declared but unused.

### Localization

`pubspec.yaml` sets `flutter_intl.enabled = true` with `main_locale: fr`, `arb_dir: lib/src/l10n`, output to `lib/src/generated`. Currently only French (`intl_fr.arb`) and English (`intl_en.arb`) exist. Use `S.current.<key>` (from `package:rual_transpo_rider_mobile/src/generated/l10n.dart`). When adding a key, add it to both ARB files and run `intl_utils:generate`.

### Models (`src/models/`)

Pattern tham chiếu: [app_user_model.dart](lib/src/models/app_user_model.dart).

- **File location** — `lib/src/models/<snake_case>_model.dart`. Một file / một model.
- **Style** — plain Dart class. **KHÔNG dùng `freezed`, KHÔNG dùng `@JsonSerializable`** dù `json_serializable` đã có trong `dev_dependencies`. Manual `fromJson` / `toJson` cho mọi model.
- **Fields** — tất cả **nullable** (`String? id;`, `int? age;`). Không dùng `required`, không dùng `final` — để có thể gán lại qua cascade.
- **Constructor** — no-arg, không `const`: `AppUserModel();`. Field khởi tạo = `null` implicit.
- **`fromJson`** — `factory` constructor, **dùng cascade `..`** để gán field trên instance vừa tạo:
  ```dart
  factory AppUserModel.fromJson(Map<String, dynamic> json) {
    return AppUserModel()
      ..email = json['email']
      ..id = json['id'];
  }
  ```
- **`toJson`** — instance method trả về `Map<String, dynamic>` literal:
  ```dart
  Map<String, dynamic> toJson() => {'id': id, 'email': email};
  ```
- **Persistence qua `SharedPrefs`** — dùng `jsonEncode(user.toJson())` để ghi và `AppUserModel.fromJson(jsonDecode(raw))` để đọc (xem [share_prefs.dart](lib/src/services/local/share_prefs.dart)). `try/catch` quanh `fromJson` vì dữ liệu cũ có thể hỏng.
- **Dùng trong VM** — không gọi API trực tiếp trong model; VM đọc response qua `api.dio.get(...)` rồi tự map sang model bằng `Model.fromJson(response.data)`.

### Persistence (`services/local/share_prefs.dart`)

Token and user model are stored via `flutter_secure_storage` (with one-time migration from `shared_preferences` on first launch). Theme mode and locale code live in `shared_preferences`. `SharedPrefs.initialise()` is called from `main()` after `setUpInjector()`.

### Networking (`services/remote/api_client.dart` + `api_interceptor.dart`)

Single `Dio` instance. `ApiInterceptor.onRequest` injects `Authorization: Bearer <token>` (skipped for `/auth/refresh`) and `language: <localeCode>`. `onError` short-circuits to a "no internet" `DioException` when connectivity is `none`, and otherwise extracts the API's `code` or `message` field. HTTP client in non-release mode accepts self-signed certs. `pretty_dio_logger` is attached in debug mode.

## Conventions

- **Page + VM co-location** — `pages/<feature>/<feature>_page.dart` + `pages/<feature>/<feature>_vm.dart`. Page name is `<Feature>Page`, VM is `<Feature>Vm`.
- **Generated asset paths** — never use string paths to `assets/icons/foo.svg`; use `AppAsset.icons.foo.path` (regenerated by `flutter_gen`).
- **Generated font family** — use `FontFamily.roboto` constant, not the string `'Roboto'`.
- **Constants in `AppConstants`** — read `AppConfig.shared.*` at static init time; default-locale/country/phone-mask constants live there too (`defaultLang = 'fr'`, `phoneCode = '+33'`, `countryCode = 'FR'`, `phoneMask = '0 00 00 00 00 00'`).
- **Per-feature folders under `components/`** (`button/`, `loading/`, `snack_bar/`) — group new shared widgets the same way.
- **Loading indicator — luôn dùng [AppCircularProgress](lib/src/components/loading/app_circular_progress.dart)**, KHÔNG dùng `CircularProgressIndicator` mặc định của Flutter. `AppCircularProgress` wrap `LoadingAnimationWidget.discreteCircle` (3 vòng, alpha giảm dần), mặc định `size = 24`, `color = AppColor.black`. Override khi cần:
  ```dart
  AppCircularProgress(size: 32, color: context.appColor.primary)
  ```
- **Tappable areas — luôn dùng [AppBounceButton](lib/src/components/button/app_bounce_button.dart)**, KHÔNG dùng `InkWell` / `GestureDetector` mặc định của Flutter. `AppBounceButton` nhận `child` + `onTap` (hoặc `onTapUp`/`onLongPress`) và tự thêm bounce/scale animation nhất quán toàn app. Ví dụ:
  ```dart
  AppBounceButton(
    onTap: () {},
    child: Container(...),
  )
  ```
- **Error visibility** — every page reaches `serverError` state via `changeState(ChangeState.serverError)`. `ServerError` widget currently renders only a centered loader (intentionally a stub).
- **1 file UI không quá 500 dòng.** Page (`*_page.dart`) chỉ giữ `Widget build()` + `create()` + `initialise()` của `MixinBasePage`; mọi sub-widget, painter, decoration helper **phải tách ra `lib/src/components/<feature>/<widget>.dart`**. Quy tắc này áp dụng cho cả `components/*.dart` — nếu component A phụ thuộc vào component B cùng feature, tách B ra file riêng. Khi vi phạm, dừng lại và refactor trước khi thêm code mới.
- **Đừng bao giờ thêm comment trong code trừ khi user yêu cầu.** Không `// TODO`, không `///` doc comment giải thích "what this does", không banner section, không header file. Code phải tự nói lên ý nghĩa qua naming + structure. Ngoại lệ duy nhất: comment bắt buộc để suppress analyzer (`// ignore: …`) hoặc comment legal/license ở đầu file.
- **Không dùng null-assertion operator `!` (`x!`) trong code viết tay.** Dùng `?.`, `??`, hoặc bind vào local non-null qua `if (x != null) { ... }` / `final v = x;` (sau khi đã null-check). `!` chỉ được phép xuất hiện ở file do generator sinh ra (auto_route, intl_utils, json_serializable). Boolean negation (`!x`, `!=`, `is!`) vẫn OK.

### Google Maps preview cards

The Rider home screen embeds a non-interactive `GoogleMap` inside a `MapPreviewCard`
(`pages/main_rider/home/widgets/map_preview_card.dart`). Conventions:

- **API key** — read at startup via `AppBaseUrl.googleMapsApiKey` (mirrors the
  `revenueCatApiKey` iOS/Android branch). Threaded into `AppConfig.shared.googleMapsApiKey`.
  Platform keys live in `.env*` as `GOOGLE_API_KEY_IOS` / `GOOGLE_API_KEY_ANDROID`.
  Native side: `Info.plist` `GMSApiKey` (set via xcconfig User-Defined Build Setting
  `GOOGLE_MAPS_API_KEY`) and Android manifest meta-data `com.google.android.geo.API_KEY`
  (Gradle placeholder `${GOOGLE_MAPS_API_KEY}` from `defaultConfig.manifestPlaceholders`).
- **Custom marker icons** — never use `BitmapDescriptor.defaultMarker` for branded
  markers. Use `SvgMarker.fromAsset(...)` from `lib/src/utils/svg_marker.dart`.
  The helper rasterizes an SVG via `flutter_svg`'s `vg.loadPicture(SvgStringLoader(...), null)`
  and wraps the result in `BitmapDescriptor.bytes`. For an "active" marker with a halo,
  pass `haloColor` and `haloMultiplier` — the halo is painted on the same canvas before
  the icon. Result is cached by `(asset, size, haloColor, haloMultiplier)`.
- **Preview-mode `GoogleMap`** — always disable user gestures for embedded previews:
  `scrollGesturesEnabled`, `zoomGesturesEnabled`, `rotateGesturesEnabled`,
  `tiltGesturesEnabled`, `myLocationButtonEnabled`, `compassEnabled`,
  `mapToolbarEnabled`, `zoomControlsEnabled` all set to `false`.
  Prefer `liteModeEnabled: true` for non-interactive cards to save memory.
- **Tapping the card** — wrap `GoogleMap` in `InkWell` (with `clipBehavior: Clip.antiAlias`
  on a `Material`) and pass `consumeTapEvents: false` on every marker so the tap
  bubbles to the full-map navigation handler.
